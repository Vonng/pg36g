## 1) 章节定位（一句话）
用一个可复现的并发支付案例，让读者先“看见异常”，再完成隔离级别选型，并落地可上线的重试与幂等防御。

## 2) 学习完成标准（3-5 条，必须可验证）
1. 能在 `READ COMMITTED` 下稳定复现至少 1 次 `丢失更新`（20 轮并发演练内）。
2. 能在 `REPEATABLE READ` 下复现至少 1 次 `写偏差`（主线或支线案例）。
3. 能给出 `RC/RR/SER` 选型决策表，包含违规次数、`P95`、失败率三项数据。
4. 能实现 `40001` 重试（最多 3 次）与 `幂等键` 去重，并通过 1000 次并发请求验证重复扣款为 0。
5. 能产出 ch11 可直接使用的“事务契约卡”（隔离级别、重试策略、幂等规则、验收脚本）。

## 3) 章节边界
- 本章要讲什么（5-7 条）
1. 先建并发基线：定义业务不变量与可接受冲突上限。
2. 在主线案例中复现 `RC` 下的 `丢失更新`。
3. 在主线案例中复现 `RR` 下的 `写偏差`，并用支线案例做对照。
4. 对 `RC/RR/SER` 做数据化选型，而不是“凭经验”选型。
5. 落地两层防御：SQL 原子化 + 应用侧重试幂等。
6. 建立可回归验收标准，并输出给 ch11 的交付物。
7. 本章首次引入术语共 12 个：`并发异常`、`隔离级别`、`读已提交（RC）`、`可重复读（RR）`、`可串行化（SER）`、`丢失更新`、`写偏差`、`幻读`、`序列化失败（40001）`、`事务重试`、`幂等键`、`冲突预算`。

- 本章明确不讲什么（3-5 条）
1. 发布流水线编排细节（CI/CD 工具链、审批流实现）。
2. 灾备、容灾、PITR、故障切换处置专题。
3. PostgreSQL 源码级并发控制实现细节。
4. 全量性能调参与容量规划专题。

## 5) 实战实验设计
实验 A（基础）  
目标：复现两类并发异常，并完成隔离级别初次选型。  
前置条件：已完成 ch09 的压测环境、主线 SQL 基线与索引方案。  
步骤：  
1. 执行 `sql/ch10_setup.sql` 初始化主线与支线数据。  
2. 在 `RC` 下运行双会话脚本，复现 `丢失更新`。  
3. 在 `RR` 下运行并发脚本，复现 `写偏差`（主线或支线至少 1 次）。  
4. 在 `RC/RR/SER` 下分别跑 200 次并发请求。  
5. 记录违规次数、`P95`、失败率，形成决策表。  
验收标准：  
1. `RC` 下 `丢失更新` 复现成功（>=1 次）。  
2. `RR` 下 `写偏差` 复现成功（>=1 次）。  
3. 形成包含三项指标的隔离级别决策矩阵。  
4. 明确主线事务最终隔离级别与理由（数据可追溯）。

实验 B（进阶）  
目标：落地 `SER + 40001 重试 + 幂等键`，建立发布前可回归验收。  
前置条件：实验 A 完成；有应用侧事务入口可改造。  
步骤：  
1. 主线事务切到 `SER`，捕获 `40001`。  
2. 实现最多 3 次重试与退避策略。  
3. 引入 `request_id` 幂等键并建立唯一约束。  
4. 执行 1000 次并发请求（建议 `c=64`），统计成功率与重试次数分布。  
5. 运行验收 SQL 检查重复扣款、余额越界、日限额越界。  
验收标准：  
1. 重复扣款数为 `0`。  
2. 业务违规数为 `0`（余额不为负、日限额不超标）。  
3. 最终失败率 `<=0.5%`。  
4. 产生可复跑验收脚本与结果归档。

## 6) 常见误区与纠偏（5 条）
1. 误区：`ch09` 索引做好了，并发正确性自然没问题。纠偏：索引只解决“快”，不保证“对”。  
2. 误区：`RR` 足够解决所有并发异常。纠偏：`RR` 仍可能出现 `写偏差`。  
3. 误区：用 `SER` 后不用改应用。纠偏：必须处理 `40001` 并实现 `事务重试`。  
4. 误区：有重试就不需要幂等。纠偏：无 `幂等键` 会出现重复执行副作用。  
5. 误区：只看吞吐和延迟。纠偏：必须同时看业务违规数与冲突失败率。
