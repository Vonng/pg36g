## 1) 章节定位（一句话）
把 `ch05` 的查询、事务、锁原理，固化为“可执行 SQL 规约 + 可量化评审清单”，让每次 SQL 变更都能稳定通过评审，并为 `ch07` 的执行计划分析提供统一输入。

## 2) 学习完成标准（3-5 条，必须可验证）
- 能用统一清单完成 1 次 SQL 评审，`P0` 项 0 漏项，整体得分 `>= 85/100`。  
- 能对给定 3 条问题 SQL 至少识别 6 处违规并提交修正版。  
- 主线案例中提交 `before/after` 两版 `EXPLAIN (ANALYZE, BUFFERS)`，各执行 3 次，结果集一致且耗时下降 `>= 30%`。  
- 并发演练后，`pg_locks` 中目标事务等待条数从 `>=1` 降到 `0`。  
- 最终交付 4 份可审计产物：规约映射表、评审清单、回归脚本、验收记录。

## 3) 章节边界
本章要讲什么（5-7 条）
- 规约如何从“经验口号”变成“可执行检查项”。

- 写入 SQL 与事务规约（短事务、固定锁顺序、幂等）。  
- DDL/索引变更的上线与回滚约束。

## 5) 实战实验设计
实验 A（基础）  
目标：把“问题 SQL”修到可评审通过。  
前置条件：已有 `orders/order_items/inventory` 测试表；准备 3 条问题 SQL。  
步骤：  
1. 执行问题 SQL，记录耗时与结果行数。  
2. 按 6.2 与 6.3 规约改写 SQL。  
3. 对改写前后各执行 3 次 `EXPLAIN (ANALYZE, BUFFERS)`。  
4. 用 20 项评审清单打分并标注 `P0` 项。  
验收标准：  
1. `P0` 项全部通过。  
2. 评分 `>=85`。  
3. 结果集一致（行数与校验值一致），且关键 SQL 耗时下降 `>=30%`。  

实验 B（进阶）  
目标：完成一次“并发冲突修复 + 评审门禁通过”的闭环。  
前置条件：两个会话可并发执行；已准备主线案例事务脚本。  
步骤：  
1. 会话 A 持锁更新库存，会话 B 执行支付更新并观察等待。  
2. 引入规约：固定锁顺序、缩短事务、设置 `lock_timeout='2s'`、幂等写入。  
3. 再次执行并发脚本，采集 `pg_locks` 与执行计划记录。  
4. 生成回归脚本并跑全量验证。  
验收标准：  
1. 无死锁，锁等待超时为 `0`。  
2. `pg_locks` 中目标等待条数为 `0`。  
3. 关键 SQL 的估算行数偏差（`actual/estimate`）控制在阈值内（`<=10`）。  
4. 回归脚本通过率 `100%`。  

## 6) 常见误区与纠偏（5 条）
1. 误区：评审只看 SQL 风格。纠偏：先过正确性与并发安全，再看风格。  
2. 误区：`SELECT *` 省事。纠偏：必须显式列，避免列漂移与无效 I/O。  
3. 误区：事务越大越安全。纠偏：最小事务边界，减少锁持有时间。  
4. 误区：有索引就不会慢。纠偏：评审必须带执行计划与偏差记录。  
5. 误区：评审结论口头同步即可。纠偏：必须有清单分数、回归脚本、验收记录三件套。
