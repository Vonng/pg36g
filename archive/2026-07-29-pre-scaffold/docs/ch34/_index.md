## 1) 章节定位（一句话）
承接 `ch33` 完成故障切换后的不稳定期，本章聚焦在高压 `20` 分钟内用流量调度与分级降级保住核心业务，并给出是否升级到 `ch35` 的量化判定。

## 2) 学习完成标准（3-5 条，必须可验证）
1. 能在 `5` 分钟内读取 `docs/ch33/ch34_input.yaml` 并产出可执行调度单（字段完整率 `100%`）。
2. 能在 `8` 分钟内完成“写入口固定 + 读流量切流”一级动作，核心写请求成功率连续 `10` 分钟 `>= 99.9%`。
3. 当阈值触发时，能在 `3` 分钟内执行二级降级（限流/熔断/只读），核心接口成功率连续 `15` 分钟 `>= 99.5%`。
4. 完成不少于 `6` 项检查（延迟、错误率、连接数、事务超时等），通过率 `100%`。
5. 能输出 `docs/ch34/ch35_input.yaml`，并对升级触发条件给出明确 Yes/No 结论（字段完整率 `100%`）。

## 3) 章节边界
本章要讲什么（5-7 条）
1. 如何接收 `ch33` 交接输入并设定止血目标。
2. 如何在高压下快速划分核心与非核心流量。
3. 如何执行一级流量调度（写入口固定、读入口权重切流）。
4. 如何执行二级降级（限流、熔断、只读降级）。
5. 如何建立 `15` 分钟滚动控制环，动态调度与回切。
6. 如何处理一个典型支线：只读池失稳时的摘流止血。
7. 如何封板交付并决定是否升级 `ch35`。

本章明确不讲什么（3-5 条）
1. 不讲故障切换与故障主重建细节（已在 `ch33`）。
2. 不讲极限数据抢救与取证操作细节（`ch35` 主体内容）。
3. 不讲年度治理、组织流程建设、长期平台规划。
4. 不讲工具大全或概念大全式堆砌。

## 5) 实战实验设计
实验 A（基础）  
目标：完成一次“一级调度 + 二级降级”的标准止血闭环。  
前置条件：`docs/ch33/ch34_input.yaml` 已存在；可调整 LB 权重；有压测或回放流量。  
步骤：  
1. 读取交接输入并确认 `rw/ro` 端点与阈值。  
2. 执行一级动作：固定写入口、读流量按权重切流。  
3. 注入读压力并观察延迟；超阈值后执行二级降级。  
4. 连续观测 `15` 分钟并按门槛回调权重。  
5. 输出调度与降级操作记录。  
验收标准：  
1. 核心写成功率连续 `10` 分钟 `>= 99.9%`。  
2. 延迟触发后二级降级生效时间 `<= 3` 分钟。  
3. 核心接口成功率连续 `15` 分钟 `>= 99.5%`。  
4. 至少 `6` 项检查通过率 `100%`。  

实验 B（进阶）  
目标：在“只读池失稳”场景完成摘流止血，并形成 `ch35` 升级判定交付。  
前置条件：实验 A 通过；可模拟只读节点高延迟或不可用。  
步骤：  
1. 模拟只读池连续超阈值。  
2. 执行支线摘流：下线异常只读入口，保留核心读写。  
3. 启用非核心功能退化并限制非核心并发。  
4. 连续观测 `15` 分钟，评估是否仍超出保护阈值。  
5. 输出 `docs/ch34/ch35_input.yaml` 与升级判定。  
验收标准：  
1. 摘流动作完成时间 `<= 2` 分钟。  
2. 主库活跃连接数在 `5` 分钟内降到上限的 `70%` 以下。  
3. 核心路径 `p95` 延迟连续 `15` 分钟 `<= 500ms`。  
4. `ch35` 输入字段完整率 `100%`，升级结论唯一且可追溯。  

## 6) 常见误区与纠偏（5 条）
1. 误区：先“一刀切降级”再看影响。纠偏：先做流量分级，再按优先级逐级动作。  
2. 误区：只改数据库参数，不改入口路由。纠偏：先固定写入口、再做读切流，最后再动数据库侧降级。  
3. 误区：降级触发条件明确，但回切门槛缺失。纠偏：同一套阈值必须包含触发与回切双门槛。  
4. 误区：只读池故障时把全部读流量压回主库。纠偏：先摘流异常只读，再退化非核心读，保护主库写能力。  
5. 误区：执行了止血动作但没留痕。纠偏：所有动作记录时间戳、操作者、命令与结果，作为 `ch35` 输入。
