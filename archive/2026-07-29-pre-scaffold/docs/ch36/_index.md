## 5) 实战实验设计
- 实验 A（基础）：目标、前置条件、步骤、验收标准  
目标：完成一次“事实冻结-根因分层-改进项池”闭环。  
前置条件：`docs/ch35/ch36_input.yaml` 可用；具备事故窗数据查询权限；有统一复盘模板。  
步骤：  
1. 校验并冻结 `ch35` 输入，生成事实基线。  
2. 量化影响并统一损失口径。  
3. 完成根因分层矩阵并排除伪因。  
4. 生成改进项池，排序并选出 Top5。  
5. 输出复盘报告与改进台账。  
验收标准：  
1. `docs/ch36/retro_report.md` 存在，且事件时间线 `>=8`。  
2. 主因结论唯一，且有证据编号可回溯。  
3. `docs/ch36/improvement_backlog.yaml` 改进项 `>=8`，字段完整率 `100%`。  
4. Top5 每条都有“当前值+目标值+截止日期”。

- 实验 B（进阶）：目标、前置条件、步骤、验收标准  
目标：将 Top3 改进固化到平台并用对照演练验证收益。  
前置条件：实验 A 通过；有演练环境；可执行 SOP/告警/配置变更。  
步骤：  
1. 选取 Top3（预防 1 条、检测 1 条、处置 1 条）。  
2. 完成平台映射与闸门配置。  
3. 执行 R1 演练并记录基线指标。  
4. 应用改进后执行 R2 演练。  
5. 对比指标并形成 90 天演进计划。  
验收标准：  
1. Top3 映射项全部有责任人和到期日。  
2. R2 相比 R1：`MTTD` 下降 `>=30%`，`MTTR` 下降 `>=20%`。  
3. 变更闸门至少拦截 `1` 次故意注入的不合规变更。  
4. `docs/ch36/roadmap_90d.md` 包含 `D30/D60/D90` 且每段至少 1 条量化退出标准。

## 6) 常见误区与纠偏（5 条）
1. 误区：复盘只写过程纪要。纠偏：必须有量化影响、证据编号、验收门槛。  
2. 误区：把根因写成“某人失误”。纠偏：强制分层到触发因/放大因/缺失控制。  
3. 误区：改进项只列动作不列指标。纠偏：每条改进必须绑定可测 metric。  
4. 误区：改进项过多且同权。纠偏：统一优先级矩阵，先做 Top3。  
5. 误区：复盘后不再验证。纠偏：必须做两轮对照演练并公布指标差值。
