## 1) 章节定位（一句话）
把 `ch08` 的慢 SQL 证据包，落地为可上线、可回归、可维护的索引方案，并控制并发副作用。

## 2) 学习完成标准（3-5 条，必须可验证）
1. 能基于同一条主线 SQL 产出至少 3 个 `索引候选`，并给出最终选型理由（含 SQL 证据）。
2. 能完成索引上线前后各 20 次回归，主线 SQL 的 `P95` 下降 `>=35%`，且结果行数一致。
3. 能使用 `CREATE INDEX CONCURRENTLY` 完成在线建索引，过程中 `锁等待` 无单次超过 `3s`。
4. 能识别并处理至少 1 个 `冗余索引`，并证明写入吞吐下降不超过 `10%`。
5. 能完成一次 `索引膨胀` 治理（`REINDEX CONCURRENTLY`），并验证索引体积下降 `>=20%`。

## 3) 章节边界
本章要讲什么（5-7 条）
1. 如何把 `ch08` 的证据（主线 SQL、基线、回归数据）转成 `索引候选`。
2. 如何做 `复合索引` 选型与顺序验证。
3. 如何在主线与支线场景中取舍 `覆盖索引` 与 `部分索引`。
4. 如何用 `并发建索引` 做在线变更并监控 `锁等待`。
5. 如何治理 `冗余索引`，降低 `写放大`。
6. 如何识别 `索引膨胀` 并用 `并发重建索引` 做修复。
7. 本章新增术语仅 11 个：`索引候选`、`复合索引`、`覆盖索引`、`部分索引`、`回表`、`并发建索引`、`锁等待`、`冗余索引`、`写放大`、`索引膨胀`、`并发重建索引`。

本章明确不讲什么（3-5 条）
1. 分布式架构评测、分片方案对比。
2. 扩展生态盘点（全文、向量、GIS 等专题选型）。
3. PostgreSQL 内核源码级索引实现细节。
4. 全量参数调优与硬件容量规划。

## 5) 实战实验设计
实验 A（基础）  
目标：完成“选型 -> 建索引 -> 回归验收”的最小闭环。  
前置条件：已完成 `ch08` 主线 SQL 基线（20 次样本、`P95`、结果行数）。  
步骤：  
1. 从 `ch08` 主线 SQL 生成 3 个 `索引候选`。  
2. 对 2 个候选做 A/B（复合索引顺序）并跑 `EXPLAIN (ANALYZE, BUFFERS)`。  
3. 选择 1 个最终方案，执行 `CREATE INDEX CONCURRENTLY`。  
4. 上线后主线 SQL 再跑 20 次，记录 `P95` 与结果行数。  
5. 采样 `锁等待`，保存上线窗口内等待明细。  
验收标准：  
1. 主线 SQL `P95` 下降 `>=35%`。  
2. 结果行数与上线前一致。  
3. 上线过程单次 `锁等待` 不超过 `3s`。  
4. 形成可回滚 DDL（`DROP INDEX CONCURRENTLY`）。

实验 B（进阶）  
目标：完成“冗余治理 + 膨胀治理 + 并发副作用控制”。  
前置条件：实验 A 完成；具备写入压测脚本（或 `pgbench`）。  
步骤：  
1. 采集索引使用率与大小基线（`pg_stat_user_indexes`、`pg_relation_size`）。  
2. 识别 1 个 `冗余索引`，在压测下执行 `DROP INDEX CONCURRENTLY`。  
3. 识别 1 个 `索引膨胀` 对象，执行 `REINDEX INDEX CONCURRENTLY`。  
4. 主线 + 支线各跑 20 次回归；同时记录写入吞吐与 `锁等待`。  
5. 输出变更前后对照与 ch10 交接数据。  
验收标准：  
1. 至少 1 个 `冗余索引` 被清理且有回滚 SQL。  
2. 目标索引体积下降 `>=20%`。  
3. 写入吞吐下降不超过 `10%`。  
4. `锁等待` 超过 `5s` 的事件数为 `0`。  
5. 主线/支线结果行数保持一致。

## 6) 常见误区与纠偏（5 条）
1. 误区：慢 SQL 一律先建索引。纠偏：先基于 `ch08` 证据筛选 `索引候选`。  
2. 误区：复合索引列顺序无所谓。纠偏：必须做顺序 A/B 对比。  
3. 误区：只看查询变快，不看写入代价。纠偏：同步评估 `写放大`。  
4. 误区：高峰期直接重建索引。纠偏：只用 `并发重建索引` 并观测 `锁等待`。  
5. 误区：删掉低使用索引就结束。纠偏：保留回滚 SQL 并做回归验证。
