## 3) 章节边界
本章要讲什么（5-7 条）  
1. 基于 `ch17` 的 `risk_*` 接口做平台化替代起点，不重建业务模型。  
2. 先做最小替代闭环，再抽象能力地图。  
3. 输出“需求 -> PostgreSQL 能力 -> 替代结果”的能力地图。  
4. 给出可执行的决策边界与打分口径。  
5. 按迁移波次设计替代路径与回退点。  
6. 用统一验收门禁验证正确性、性能与成本。  
7. 向 `ch19` 交付部署基线输入，而不是运维处置细节。  

本章明确不讲什么（3-5 条）  
1. 不讲高可用拓扑、备份体系、故障处置流程。  
2. 不做中间件工具大全或选型百科。  
3. 不展开组织治理、SLA 制度设计。  
4. 不给出跨章的完整部署操作手册（留给 `ch19`）。

## 5) 实战实验设计
实验 A（基础）  
目标：完成主线“盘点 -> 最小闭环 -> 边界定论”。  
前置条件：`ch17` 验收脚本通过；`risk_*` 接口可用；有 200 条回放样例。  
步骤：  
1. 执行 `01_inventory.sql`，确认主线/支线依赖清单。  
2. 执行 `02_min_loop.sql`，建立兼容模式；执行 `02_diff_check.sql` 做双写对比。  
3. 执行 `03_capability_map.sql`，产出能力地图。  
4. 执行 `04_boundary_score.sql`，完成 `GO/HOLD/NO-GO` 打分。  
验收标准：  
1. 双写对比 `diff_count=0`。  
2. 主线候选项全部有结论，`undecided=0`。  
3. `capability_map.md` 与 `decision_boundary.md` 字段完整率 `100%`。  

实验 B（进阶）  
目标：完成主线三波次替代并交付 `ch19` 部署输入。  
前置条件：实验 A 通过；有 `ch17` 的 `P95` 基线与权限矩阵。  
步骤：  
1. 依次执行 `05_wave1.sql`、`05_wave2.sql`、`05_wave3.sql`，并记录每波次回退点。  
2. 执行 `05_branch_wave.sql` 验证支线不影响主线决策。  
3. 执行 `06_acceptance.sql` 完成功能/性能/成本门禁。  
4. 执行 `07_handoff_export.sql` 导出 `ch19_input.yaml`。  
验收标准：  
1. 三波次切换检查项通过率 `100%`。  
2. 主链路 `P95` 回退 `<=15%`，错误率不高于 `ch17` 基线。  
3. 主线外部依赖数量按计划下降（以 `inventory.csv` 对比为准）。  
4. `ch19_input.yaml` 结构校验 `PASS`。  

## 6) 常见误区与纠偏（5 条）
1. 误区：把“平台化替代”当成“全部替代”。纠偏：先按决策边界打分，`NO-GO` 明确保留。  
2. 误区：先选技术再找场景。纠偏：先做依赖盘点和目标冻结，再选替代路径。  
3. 误区：POC 一次通过就全量切换。纠偏：必须按迁移波次推进并保留回退点。  
4. 误区：只看功能正确，不看成本。纠偏：验收门禁必须包含成本台账与资源画像。  
5. 误区：把运维处置细节塞进本章。纠偏：本章只交付 `ch19` 输入，不展开下卷内容。
