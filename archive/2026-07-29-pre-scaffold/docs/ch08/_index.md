## 1) 章节定位（一句话）
把 `ch07` 的“会看执行计划”升级为“能闭环处理慢 SQL”：完成定位、验证、回归，并交付可直接进入 `ch09` 的索引候选证据包。

## 2) 学习完成标准（3-5 条，必须可验证）
1. 能用 `pg_stat_statements` 选出 1 条主线慢 SQL（含 `queryid/calls/total_exec_time`），并说明为何优先处理。  
2. 能为主线 SQL 建立 20 次可复现基线，给出 `avg` 与 `P95`，并记录结果行数。  
3. 能从 `EXPLAIN (ANALYZE, BUFFERS)` 标出 1 个热点节点（节点耗时占总耗时 `>=40%`）。  
4. 能给出 1 条可检验诊断假设，并完成一次单变量对照实验。  
5. 能完成回归验证：主线 SQL 的 `P95` 下降 `>=30%`，且结果行数与基线一致。

## 3) 章节边界
- 本章要讲什么（5-7 条）
1. 如何从全量慢 SQL 中选“最值钱”的诊断对象。  
2. 如何建立可复现实验基线，避免“偶然变快”。  
3. 如何用计划与统计证据定位热点和估算失真。  
4. 如何把“猜测”变成“可证伪的假设”，并做对照验证。  
5. 如何做回归检查，覆盖主线与参数变化场景。  
6. 如何沉淀交付物，形成 `ch09` 可用的索引候选输入。  
7. 本章新增术语控制为 11 个：`queryid`、`基线`、`P95`、`热点节点`、`估算偏差比`、`假设`、`对照实验`、`回归脚本`、`结果一致性`、`参数漂移`、`索引候选`。  

- 本章明确不讲什么（3-5 条）
1. 索引类型大全、索引维护细节与选型对比（留给 `ch09`）。  
2. 监控平台建设、告警体系、SRE 值班流程。  
3. PostgreSQL 内核源码级执行器分析。  
4. 参数调优大全、硬件容量规划。

## 5) 实战实验设计
- 实验 A（基础）：目标、前置条件、步骤、验收标准  
目标：完成“选对象 -> 建基线 -> 定热点 -> 提假设”的最小诊断闭环。  
前置条件：已启用 `pg_stat_statements`；有订单与支付样本数据；可执行固定回放 SQL。  
步骤：  
1. 回放业务查询 3-5 分钟。  
2. 从 `pg_stat_statements` 选出主线 SQL。  
3. 固定参数执行 20 次，记录 `avg/P95/rows`。  
4. 执行 `EXPLAIN (ANALYZE, BUFFERS)` 3 次，定位热点节点。  
5. 计算至少 3 个关键节点的估算偏差比，写出 1 条假设。  
验收标准：  
1. 主线 SQL 明确且含 `queryid`。  
2. 基线数据完整（20 次样本 + `avg/P95/rows`）。  
3. 至少 1 个热点节点被量化（耗时占比 `>=40%`）。  
4. 至少 1 条可检验假设被写明（含证据来源）。  

- 实验 B（进阶）：目标、前置条件、步骤、验收标准  
目标：完成“验证 -> 回归 -> 交付 ch09”的完整闭环。  
前置条件：实验 A 完成；已有 1 条可检验假设。  
步骤：  
1. 记录优化前基线（主线 20 次，支线 20 次）。  
2. 执行单变量改动（如 `ANALYZE` 或 SQL 改写）。  
3. 记录优化后同规模样本（主线 20 次，支线 20 次）。  
4. 对比 `avg/P95` 与结果行数，判断是否有效且无副作用。  
5. 输出索引候选清单，标注优先级与预期收益。  
验收标准：  
1. 主线 `P95` 下降 `>=30%`。  
2. 支线 `P95` 不劣化超过 `10%`。  
3. 主线与支线结果行数与优化前一致。  
4. 形成可复查交付件：基线表、A/B 对照表、回归矩阵、索引候选清单。  

## 6) 常见误区与纠偏（5 条）
1. 误区：直接改 SQL，不做基线。纠偏：先固定参数做 20 次样本。  
2. 误区：一次改多个因素。纠偏：严格单变量对照实验。  
3. 误区：只看平均耗时。纠偏：必须同时看 `P95`。  
4. 误区：看到顺序扫描就判错。纠偏：先看节点耗时占比与偏差比。  
5. 误区：主线变快就收工。纠偏：必须带支线参数做回归。
